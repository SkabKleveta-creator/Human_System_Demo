# P0_IMPLANT_REFRAME_NOTE.md

## Purpose
This document records the approved scope reset for the current Human System playable prototype. It preserves the existing 4-room proof slice while establishing a controlled cybernetic framing that supports the current gameplay loop.

## Current Build Identity
**The Human System — P0-A Remember Mara**

Build type: narrative proof slice. Current status: playable.

## Current Gameplay Loop
1. Wake after Patch 17.
2. Learn that the system claims forty-seven residents.
3. Explore four rooms.
4. Preserve three contradictions.
5. Confirm Mara existed.
6. Trigger the ending.

## Current Evidence Model
- **Warm Mug** — physical residue.
- **Tomas' Song** — cultural residue.
- **Blank Clinic Record** — system residue.

## Scope Reduction
This build is intentionally smaller than the broader Human System concept. The goal is to preserve a functioning playable center before expanding the project.

## Features Not Present
Full RPG progression, combat, enemy encounters, inventory systems, skill trees, classes, cybernetic upgrade trees, multiple endings, Ren, DEFERRED, dog evidence, drift evidence, faction systems, resistance movements, rebellion narratives.

Absence of these features is not a defect.

## Cybernetic Reframe
Cybernetics replace magic. The Human System exists inside a controlled AI-managed environment. The proof slice is a small diagnostic window into that larger condition.

## Residual Scanner Implant
Status: approved concept, not yet implemented.

Purpose: explain why the player can perceive contradiction after a correction event. The implant surfaces residual signals that should no longer exist.

Supports: contradiction recognition, evidence preservation, continuity investigation, residue detection.

Does not support: combat, progression systems, character builds, power acquisition, resource management.

## Approved Future Changes
- Establish implant irregularity during startup.
- Reframe evidence interactions as residual readings.
- Clarify AI/system and correction-event terminology.
- Update evidence-log wording.

## Not Approved
Combat mechanics, multiple implants, implant load systems, battery systems, equipment systems, inventory systems, skill trees, additional rooms, additional evidence categories, major narrative expansion, full RPG implementation, canon reconciliation efforts.

## Source Hierarchy
PROJECT_DIRECTION_LOCK.md governs setting and strategy. This note governs proof-slice implementation boundaries. If conflicts occur, PROJECT_DIRECTION_LOCK.md takes precedence.

## Development Priority
Protect the playable center. Future changes should strengthen the idea that a correction can remove a person from the record while leaving evidence humans still recognize as meaningful.
